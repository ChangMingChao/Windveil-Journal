# S09: 先记一下并随手划掉 — 交互规格

> 模块：core｜阶段：Phase 2 产品设计（What）
> 上游场景：`core-01-requirements.md` 的 S09（lightweight-events 提案新增）
> 原型：`../2-page-design/core-06-lite-events-prototype.html`

**涉及页面**：`/`（P1 种下页）的「先记一下」区。轻事件不开新路由、不进未发生之地、不进已发生之书——它们是「还不值得变成愿望的念头」。

**「先记一下」区结构**

| 区域 | 元素 | 规格 |
|------|------|------|
| 入口 | 「先记一下」文字链接，主输入区下方 | 展开式：点击显示输入 + 列表；再点收起（列表随之隐藏，不占视觉空间） |
| 输入 | 单行输入 + 「记下」按钮 + 主题无关（轻事件不分类） | 上限 200 字；空内容禁用保存；保存后输入框清空可连续记录 |
| 列表 | 每条一行：内容 + 「划掉了」+「收走」；最近在上，最多渲染 8 条 | 「划掉了」= 完成（状态 done，从默认列表消失，保留行以备追溯）；「收走」= 硬删除；两者都无确认步骤 |
| 空态 | 只显示输入框 + 「想到什么小事，一句话记下它」 | 禁止「你还没有记录」句式、禁止条数统计 |

**明确不存在的元素**（验收要检查其缺失）：条数统计、时间戳展示、分类标签、提醒开关、升格为愿望按钮、任何形式的「本周已记 N 条」。

**交互流程**

1. 用户点「先记一下」→ 区域展开
2. 输入一句话 → 「记下」→ 列表置顶出现该条，输入框清空
3. 「划掉了」→ 状态转 done，行淡出消失（240ms）
4. 「收走」→ 硬删除，行立即消失
5. 全程无提醒、无 Agent、无计数

### 验收条件（交互级）

##### 正常：记录、划掉与连续记录
- **GIVEN** 「先记一下」已展开
- **WHEN** 用户记下「今晚吃火锅」，再记下「周末取快递」，然后划掉「今晚吃火锅」
- **THEN** 列表按最近在上排列；划掉后仅剩「周末取快递」；输入框每次保存后清空；无任何数字变化

##### 正常：收走与划掉的区别不被追问
- **GIVEN** 列表中有一条轻事件
- **WHEN** 用户分别尝试「划掉了」与「收走」
- **THEN** 两个动作都立即生效、都无确认弹层；「收走」后该条在任何视图（含 include_done 查询）中都不再出现；「划掉了」的条目不出现在默认列表

##### 异常：空内容双层拒绝
- **GIVEN** 输入框为空或全空白
- **WHEN** 用户尝试保存
- **THEN** 前端「记下」禁用；绕过前端直接调 API 返回 422（VALIDATION_FAILED）；不产生空记录

##### 异常：轻事件与愿望互不干扰
- **GIVEN** 用户同时持有愿望与轻事件
- **WHEN** 用户进行任意轻事件操作（记下/划掉/收走）
- **THEN** 愿望列表、提醒额度、Agent 行为全部不受影响；`/garden` 中不出现轻事件；已发生之书中不出现轻事件

> 追加到本文件交互规格之后。S02 的 near_term_todo 询问（EX-18.2）新增第三选项「先记一下」后，轻事件可能来自转换而非直接输入。

**来源标注**

| 元素 | 规格 |
|------|------|
| 转换来源的轻事件 | 与直接输入的轻事件**完全相同**地展示（同列表、同划掉/收走），不加来源徽标——用户不关心它是怎么来的 |
| 转换文案 | 转换成功后 P1 询问卡显示「已经先帮你记下来了」；轻事件列表随即包含该条 |

**明确不存在的元素**：来源徽标（「来自愿望」）、原 wish_id 的任何残留引用、转换后的确认弹层。

### 验收条件（交互级）

##### 正常：转换后轻事件立即可见可划掉
- **GIVEN** 用户在 S02 询问卡选择了「先记一下」
- **WHEN** 转换完成
- **THEN** P1 的轻事件列表包含该文本；用户可正常划掉或收走；询问卡关闭并显示「已经先帮你记下来了」
