## 一、产品类型判断与原型策略

| 判断项 | 结论 | 依据 |
|--------|------|------|
| 产品类型 | **Web 应用（移动优先，可安装为 PWA）** | 需求文档 5.1「第一版为移动优先的 Web 应用，不做原生 App、不做桌面客户端」 |
| 是否 GUI 类 | 是 → 触发 product-designer Step 5a | 交付物含图形界面 |
| 原型形式 | 可交互 HTML 页面（移动视口 375px 起） | Skill 产品类型对照表：Web 应用 → HTML 可交互页面 |
| 交互规格重点 | 页面流转、状态变化、输入校验的「非压迫式」表达 | 需求文档设计原则 1–5 |
| 技术栈参考 | `html-tailwind` 指南（移动优先、44px 触控、响应式内边距） | ui-ux-pro-max `--stack html-tailwind` |

**原型实现方式的偏离说明**：Skill 默认技术栈为 `html-tailwind`，但原型采用**手写 CSS + CSS 变量**而非 Tailwind CDN，原因是原型需要在无网络环境下直接双击打开供评审。`html-tailwind` 的全部指南（mobile-first、`min-h-[44px]` 触控、`px-4 md:px-6` 响应式内边距、`loading='lazy'`）以等价 CSS 落地，设计令牌与 `design-system.json` 一一对应。

**场景粒度复核**：S01–S06 均为多步交互路径，未发现 CRUD 级伪场景，无需回退 Phase 1 重组。

## 三、页面结构与路由

```text
/                       P1 种下一个愿望（首页 = 唯一输入入口）
/welcome                首次体验流（S01，仅新用户；完成后不再进入）
/garden                 P2 未发生之地（主界面，花园视图 / 河流视图可切换）
/garden?state=<状态>    P2 按状态筛选（deep-link，URL 反映当前视图）
/wish/:id               P3 愿望详情（含 Agent 对话、时机、准备过程）
/wish/:id#timing        P3 时机选择半屏
/wish/:id#tidy          P3 重新整理半屏（改 / 停 / 放下 / 彻底删除）
/wish/:id#recall        P3 唤回半屏（仅 `let_go` 状态可用，S07）
/book                   P4 已发生之书（按时间倒序的书页列表）
/book/:id               P5 单页记忆（可编辑补充）
/me                     P6 我的（隐私说明、提醒通道、导出、注销）
```

导航层级（底部固定导航，仅 3 项 + 1 个主动作）：

```text
┌──────────────────────────────────────────┐
│  ( 种下 )        未发生之地      已发生之书 │   ← 底部导航，44px 高触控区
│   居中主动作         默认页          书页    │
└──────────────────────────────────────────┘
```

- 「种下」为居中主动作（纸质圆形按钮），任何页面一键可达，对应需求文档「首页只有一个温暖的输入入口」。
- 「我的」不占导航位，从 P2 右上角进入，避免设置项抢夺注意力。
- 首次体验流（`/welcome`）不显示底部导航，避免中断感。

## 四、全局状态机（愿望卡）

```text
                   ┌──────────────────────────────────────┐
                   │                                      │
  [种下] ──▶ 刚种下 ──(约定时机 S03)──▶ 正在酝酿 ──(时机到达/我好像准备好了 S04)──▶ 风来了
              │                          │  ▲                                      │
              │                          │  └──(还不是现在，重新约定)               │
              │                          │                                         ▼
              │                          └◀──(先放回酝酿)────────────── 正在发生 ◀──(完成第一小步)
              │                                                          │
              └──(不必提醒)──▶ 刚种下（无提醒）                            │
                                                                         ▼
        安静放下 ◀──(安静放下 S05.2，任意状态均可)                    已经发生（S06 → 生成记忆页）
              │
              └──(重新种下 S07，保留首次种下时间与内容)──▶ 刚种下
```

状态迁移规则（全局，各页面不得违反）：

1. 任何状态均可直接迁移到「安静放下」，且不得出现二次劝阻或挽留话术（仅「彻底删除」需二次确认）。
2. 「已经发生」为终态，不再接收任何提醒；仅记忆页内容可继续补充。
3. 「刚种下」允许长期停留，系统不得因停留时长产生任何提示或视觉降级。
4. 状态回退（正在发生 → 正在酝酿）保留已记录的准备过程，不清空。
5. 状态在 UI 中必须同时以「文字标签 + 形状 + 颜色圆点」三重表达，颜色不作唯一指示。

## 五、全局交互规则

### 5.1 提醒预算（对应需求文档指标「每周提醒 ≤ 3 条」）

| 规则 | 具体行为 |
|------|---------|
| 全局周预算 | 每用户每自然周最多 3 条主动提醒（Web Push 或邮件，合计计数） |
| 超额处理 | 按用户设置时机的先后顺序顺延到下一周；被顺延的卡片在 P2 内以柔光标记呈现，不发推送 |
| 单卡去重 | 同一张卡的同一次时机只发 1 条，用户已在应用内看到该时机则不再补发 |
| 禁止合并 | 不得将多张卡合并为一条清单式提醒（如「你有 5 件事待处理」） |
| 停滞关心 | 「正在发生」满 60 天无动作时最多 1 条，且计入周预算 |
| 静默通道 | 用户可在 P6 关闭推送仅保留邮件、或全部关闭；关闭后不再有任何应用内催促标记 |

### 5.2 文案词典（强制，见需求文档 5.1 文案约束）

| 禁用 | 使用 |
|------|------|
| 任务 / 事项 | 愿望、一件事 |
| 创建 / 新建 | 种下 |
| 截止 / 逾期 / 超时 | （不存在该概念） |
| 待处理 / 未完成 | 正在等待合适的风 |
| 完成 / 已完成 / 打卡 | 已经发生、发生过 |
| 删除（列表默认动作） | 安静放下（「彻底删除」仅作二级动作） |
| 放弃 / 失败 | 安静放下 |
| 进度 X% / 连续 N 天 | （不展示任何计数） |

### 5.3 Agent 行为规范（全局）

1. **追问上限**：单次记录最多追问 1 句；用户跳过后当次不再追问，仅记录为「待未来再问」。
2. **最小下一步唯一**：一次仅给出 1 个下一步，禁止一次性输出完整计划（S04）。
3. **降级不阻塞**：Agent 不可用时先落库原话，标题回退为原话前 20 字，文案为「先替你收好了，我稍后再慢慢读它」，不暴露错误码、不要求重试。
4. **不作价值判断**：不评价愿望是否值得、是否现实，不主动建议放弃。
5. **引用原话**：所有提醒与推进文案必须引用用户自己的话，格式为「你在 <月份> 说过……」。

### 5.4 输入与可访问性

| 项 | 规格 |
|----|------|
| 文字输入 | 单行起、自动增高，上限 500 字；不设必填校验，仅空内容时禁用提交按钮 |
| 语音输入 | 长按录音，上限 60 秒；录音中显示波形与剩余秒数；松手即提交；保留原始音频 |
| 照片 | 每张愿望卡上限 9 张，`loading="lazy"`，需 alt 文本（默认取愿望标题） |
| 触控 | 全部可点击元素 ≥ 44×44px |
| 键盘 | Tab 顺序与视觉顺序一致，焦点态为 2px `clay` 描边 + 2px 偏移 |
| 图标按钮 | 必须有 `aria-label`；图标为 24×24 内联 SVG，禁用 emoji |
| 动效 | `prefers-reduced-motion: reduce` 时全部动效降级为无动画（含「风来了」光晕） |
| 空状态 | 每个空状态都有一句温暖文案 + 单一入口，禁止出现「你还没有……」句式与补齐引导 |
