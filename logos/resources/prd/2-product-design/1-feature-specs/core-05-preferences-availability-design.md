
# S08: 管理偏好与可用时段 — 交互规格

> 模块：core｜阶段：Phase 2 产品设计（What）
> 上游场景：`core-01-requirements.md` 的 S08（preferences-availability-timing 提案新增）
> 原型：`../2-page-design/core-05-preferences-availability-prototype.html`

**涉及页面**：`/me`（P6 我的）→ `#remembered`「它记得我什么」区；P3 侧的建议确认卡见 `core-02-unhappened-place-design.md` 增补

**「它记得我什么」区结构（自上而下）**

| 区域 | 元素 | 规格 |
|------|------|------|
| 顶部 | 标题「它记得我什么」+ 一句说明「这里的东西只有你能看到，也随时可以让它忘掉」 | 常规标题层级，不使用数字统计（如「12 条记忆」禁止） |
| 偏好列表 | 每条含：内容、来源徽标（「你说过的」`sprout` 绿点 /「我猜的」雾蓝空心点 + 置信档文案）、撤回（仅「我猜的」）与删除动作 | 「我猜的」条目视觉弱于「你说过的」；撤回文案「猜错了」；删除需一次确认 |
| 已撤回痕迹 | 折叠项「你看过的猜测（N 条已撤回）」 | 展开仅见撤回时间与内容；不含任何计数压力语义（不出现在默认视图） |
| 偏好声明输入 | 一行输入 + 「记下来」按钮；输入时选择主题标签（放松 / 节奏 / 同行 / 预算 / 其他） | 上限 200 字；声明成功后不弹出庆祝或引导 |
| 可用时段 | 按周一→周日排布的周视图条：每条为「周几 + 起止时间」+ 备注（可选）；新增、修改、删除 | 新增走结构化选择（周几胶囊 + 开始/结束时间步进器），禁止开放式文本时间输入；备注上限 50 字，加密存储 |
| 空状态 | 「它还什么都不知道。你想让它记住什么？」+ 单一输入入口 | 禁止「你还没有添加偏好」句式与补齐引导 |

**明确不存在的元素**（验收要检查其缺失）：记忆条数统计、模型版本或技术参数、原始对话回放入口、导出偏好的快捷按钮（导出走 P6 既有「导出全部数据」）、任何把推断内容表述为事实的文案。

**交互流程**

1. 用户在 P6 点「它记得我什么」→ 锚点滚动到该区
2. 页面并列展示偏好列表与可用时段周视图（一次请求各取所需，无分步加载）
3. 用户声明偏好 → 该条以「你说过的」徽标出现；同主题的「我猜的」条目保持原样并列（不覆盖）
4. 用户对「我猜的」条目点「猜错了」→ 该条从默认列表消失，进入已撤回痕迹
5. 用户删除任意条目（偏好或时段）→ 一次确认（「删掉后，它就真的不记得这条了」）→ 硬删除；引用该条目的未确认时机建议同步失效
6. 用户新增可用时段 → 结构化选择保存 → 用于此后「空闲周末」时机与建议的判断
7. 定期地，系统把偏好浓缩为一份「它的理解」摘要（同样可查看、可删除）；摘要仅作为建议的上下文来源，不直接展示为判断结论

### 验收条件（交互级）

##### 正常：声明一条偏好并与猜测并列
- **GIVEN** 用户在「它记得我什么」，列表中有一条「我猜的 · 大概猜的」：喜欢一个人做事
- **WHEN** 用户在声明输入框写下「其实更想和朋友一起」并保存
- **THEN** 列表新增「你说过的」条目「更想和朋友一起」，原「我猜的」条目保持原样并列展示；无「已覆盖」「已更新你的画像」类文案；刷新后两条仍在

##### 正常：撤回一条猜测
- **GIVEN** 列表中一条来源为「我猜的」的偏好
- **WHEN** 用户点「猜错了」
- **THEN** 该条立即从默认列表消失；折叠项「你看过的猜测」中出现「你撤回了它 + 时间」；P3 中引用该条目的待确认建议同步失效；重复点击撤回不产生第二条痕迹

##### 异常：删除后不留影子
- **GIVEN** 用户删除一条「你说过的」偏好
- **WHEN** 确认删除
- **THEN** 列表与已撤回痕迹中均不再出现；此后 P3 的时机建议理由不再引用它；导出的全部数据中不含它；界面无「已删除 N 条」类计数

##### 异常：可用时段的时间非法
- **GIVEN** 用户在新增可用时段
- **WHEN** 用户选择「周六 14:00 至 13:00」（结束早于开始）并保存
- **THEN** 保存按钮禁用并在步进器旁提示「结束要晚于开始」；不弹模态、不出现红色报错；用户纠正后可正常保存；不产生半写入记录
