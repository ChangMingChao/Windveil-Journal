## S05.1: 浏览未发生之地 — 交互规格

**涉及页面**：`/garden`（P2 主界面）

**页面元素**

| 区域 | 元素 | 规格 |
|------|------|------|
| 顶部 | 标题「未发生之地」、视图切换（花园 / 河流）、右上「我的」入口 | 切换为两个文字标签 + 下划线激活态（非图标猜谜） |
| 状态筛选 | 横向可滑动的状态胶囊：全部 / 刚种下 / 正在酝酿 / 风来了 / 正在发生 / 安静放下 | 激活态 `clay` 描边 + 文字加深；URL 同步为 `?state=正在酝酿`（deep-link） |
| 花园视图 | 愿望卡按种下时间倒序，双列错落（≥768px 三列） | 卡片间距 16px；卡片本身即触控区（≥44px 高），`cursor:pointer` |
| 河流视图 | 一条 `mist` 竖线贯穿，卡片按时机临近程度沿线排列 | 线条为装饰，不承载文本 |
| 愿望卡 | 标题、`种下于 YYYY 年 M 月`、原话摘要（1 行截断）、状态徽标 | 状态徽标 = 圆点 + 文字 + 形状；「风来了」额外有 2.4s 呼吸光晕 |
| 空状态 | 一句温暖文案 + 居中「种下」入口 | 见 IA 5.4 |
| 底部导航 | 种下（居中主动作）/ 未发生之地 / 已发生之书 | 固定，`safe-area-inset-bottom` 兼容 |

**明确不存在的元素**（验收要检查其缺失）：完成率、进度条、逾期标记、连续天数、未读数字角标、排序权重降级、任何红色。

**交互流程**

1. 用户点底部「未发生之地」→ `/garden`，默认花园视图 + 「全部」筛选
2. 横滑状态胶囊或点击某状态 → 列表就地过滤，URL 同步
3. 点「河流」→ 同一批卡片重排为时间河流（240ms 交叉淡入，非位移动画）
4. 点任一卡片 → `/wish/:id`
5. 顺延中的卡片（提醒被周预算顺延）在卡角显示柔光点 + 文字「本周先不打扰你」

### 验收条件（交互级）

##### 正常：按状态浏览并深链
- **GIVEN** 用户有 12 张卡片，分布于「刚种下」「正在酝酿」「风来了」「正在发生」4 种状态
- **WHEN** 用户在 `/garden` 点击状态胶囊「正在酝酿」
- **THEN** 仅展示该状态卡片，胶囊呈激活态（`clay` 描边），URL 变为 `/garden?state=正在酝酿`；刷新后筛选保持；页面内不出现完成率／逾期／连续天数／数字角标任一元素；卡片默认按种下时间倒序，切到「河流」后按时机临近排序

##### 正常：切换视图不丢失筛选
- **GIVEN** 用户处于 `/garden?state=风来了` 花园视图
- **WHEN** 用户点击「河流」
- **THEN** 视图在 240ms 内以淡入切换，筛选保持「风来了」，URL 追加视图参数；「风来了」卡片的光晕在 `prefers-reduced-motion: reduce` 下不呼吸、仅呈静态柔光

##### 异常：花园为空
- **GIVEN** 用户已将全部愿望放下或删除，当前筛选为「全部」
- **WHEN** 用户进入 `/garden`
- **THEN** 展示空状态文案「这里还什么都没有。想到什么，随时来种下它。」与居中「种下」按钮；不出现「你已经很久没有记录了」「继续保持」等句式，不出现引导补齐或成就中断提示

##### 异常：某状态下无卡片
- **GIVEN** 用户没有任何「正在发生」的愿望
- **WHEN** 用户点击状态胶囊「正在发生」
- **THEN** 展示该状态专属空文案（如「还没有什么正在发生。不着急。」），胶囊保持激活，其他状态仍可切换；不自动跳回「全部」

## S03: 为一个愿望约定属于它的时机 — 交互规格

**涉及页面**：`/wish/:id`（P3 详情）→ `#timing` 时机选择半屏 → 提醒通知

**详情页结构**（自上而下）

| 区块 | 内容 | 规格 |
|------|------|------|
| 卡头 | 标题、状态徽标、`种下于 YYYY 年 M 月` | 标题可点进入行内编辑 |
| 原话 | 「你当时说的是：……」引用块（含语音回放按钮，若有） | `quote` 字号，斜体，`ink-soft` |
| 时机 | 「什么时候再提起它」当前约定 + 「改一改」 | 未约定时显示为主动作按钮 |
| 理解 | Agent 读到的感受与条件（如「想要的是：喘口气」「条件：压力较小时」） | 可折叠，默认展开 |
| 准备过程 | 时间线（仅「正在发生」后出现） | 见 S04 |
| 对话 | Agent 与用户的往来（见 S04） | — |
| 底部 | 「我好像准备好了」主动作、「整理一下」次动作 | 主动作 `clay`，次动作描边 |

**时机选择半屏（6 个自主选项，无输入表单）**

| 选项 | 二级选择 | 卡面显示 |
|------|---------|---------|
| 某个季节到来 | 春 / 夏 / 秋 / 冬 | 正在等待合适的风：入冬 |
| 某个月份或纪念日 | 月份选择 / 日期选择 | 正在等待合适的风：明年 3 月 |
| 多久之后再想想 | 1 / 3 / 6 / 12 个月 | 正在等待合适的风：三个月后 |
| 当我有一个空闲周末时 | — | 正在等待合适的风：一个空闲的周末 |
| 当我主动提到很累时 | — | 正在等待合适的风：你说累的时候 |
| 不必提醒，我自己会想起 | — | 你说你会自己想起它 |

**通知规格**

- 文案模板：`你在 <种下月份> 说过<愿望原话摘要>，<时机描述>了。`
- 动作：「我好像准备好了」/「还不是现在」（通知内动作 + 应用内同款按钮）
- 通道：Web Push 优先，未授权或 iOS 未添加主屏时改用邮件
- 预算：受 IA 5.1 周预算 3 条约束

### 验收条件（交互级）

##### 正常：约定季节触发并收到通知
- **GIVEN** 用户在 `/wish/w-102`（「学会滑雪」，状态「刚种下」），当前为 2026 年 9 月
- **WHEN** 用户点「什么时候再提起它」→ 选「某个季节到来」→ 选「冬」→ 点「就这样」
- **THEN** 半屏关闭，卡片状态徽标变为「正在等待合适的风：入冬」（雾蓝深文字 + 双叶形状），`/garden` 中该卡同步更新；到达时机后收到 1 条通知，文案为「你在九月说过想在冬天学会滑雪，冬天到了。」并带两个动作；同一时机不再发送第二条

##### 正常：时机到达但选择「还不是现在」
- **GIVEN** 某卡时机已到达，用户已收到通知并打开 `/wish/:id`
- **WHEN** 用户点击「还不是现在」
- **THEN** 出现时机半屏且默认选中「多久之后再想想 → 3 个月」，用户确认后状态保持「正在酝酿」；卡片不出现任何逾期标记、不显示「已顺延 N 次」、在 `/garden` 中的排序位置不下降；文案为「好，那就等等」

##### 异常：选择不必提醒
- **GIVEN** 用户在时机半屏
- **WHEN** 用户选择「不必提醒，我自己会想起」并确认
- **THEN** 状态保持「刚种下」，卡面文字为「你说你会自己想起它」；该愿望不再进入任何提醒队列；详情页「什么时候再提起它」仍可再次点击补设时机

##### 异常：同周多张卡片触发，超出提醒预算
- **GIVEN** 用户有 5 张卡的时机落在同一自然周，周预算为 3 条
- **WHEN** 这些时机相继到达
- **THEN** 本周仅发送前 3 条（按用户设置时机的先后顺序），第 4、5 张卡在 `/garden` 中显示柔光点与「本周先不打扰你」，其提醒顺延至下周；不出现「你有 5 件事待处理」一类合并式提醒

## S04: 风来了，开始第一小步 — 交互规格

**涉及页面**：`/wish/:id` 的对话区与准备过程时间线

**对话区元素**

| 元素 | 规格 |
|------|------|
| Agent 气泡 | 纸色 `card` 底，左对齐，最多 3 行后展开；一次仅含 1 个下一步 |
| 下一步卡 | 内嵌于 Agent 气泡下方，含步骤文字 + 「做完了」+「还是太难了，换一个更小的」 | 
| 用户气泡 | `paper` 底 + `line` 描边，右对齐 |
| 输入行 | 单行输入 + 语音，固定在对话区底部 |
| 准备过程时间线 | 每条含步骤文字 + 完成时间；节点为 `sprout` 圆点 | 
| 禁止元素 | 计划清单、剩余步骤数、预计耗时、截止日期、完成百分比 |

**交互流程**

1. 入口二选一：通知／卡片上点「我好像准备好了」，或详情页底部主动作 → 状态转「风来了」，卡面出现柔光
2. Agent 在对话区给出 1 个最小下一步（限定：可在 5 分钟内独立完成）
3. 用户点「做完了」→ 该步骤写入准备过程时间线（含完成时间）→ 状态转「正在发生」→ Agent 追加下一个更小的一步
4. 用户点「还是太难了，换一个更小的」→ Agent 在同一轮内替换为更轻的步骤（≤5 分钟、不花钱、不联系他人），且不重复被拒绝过的步骤
5. 用户主动要求时，Agent 才逐步协助：确定日期 → 整理预算 → 规划行程 → 建立提醒

### 验收条件（交互级）

##### 正常：完成第一小步并进入「正在发生」
- **GIVEN** `/wish/w-101`（「去海边待两天」）状态为「正在酝酿」
- **WHEN** 用户点底部「我好像准备好了」，Agent 给出「今晚花两分钟，收藏一张你想看的海的照片」，用户点「做完了」
- **THEN** 状态徽标变为「正在发生」（低饱和绿深文字 + 抽枝形状）；准备过程时间线新增 1 条含完成时间的记录；Agent 仅追加 1 个新步骤，对话区内不出现步骤清单、剩余数量或百分比；详情页任何位置不出现截止日期字段

##### 正常：要求一个更小的开始
- **GIVEN** Agent 已给出「这周挑一个周末的日期」，用户认为太重
- **WHEN** 用户点击「还是太难了，换一个更小的」
- **THEN** 同一轮内替换为更轻步骤（如「先在地图上收藏一个你想去的海」），新步骤满足 ≤5 分钟、不涉及花钱与联系他人；被拒绝的步骤不再出现；对话区不出现「你已经拒绝 N 次」类计数

##### 异常：进入「正在发生」后 60 天无动作
- **GIVEN** 某卡状态为「正在发生」，最近一次用户动作距今 60 天
- **WHEN** 系统执行状态回看
- **THEN** 最多发送 1 条关心（「那件事最近怎么样了？还想继续吗？」，计入周预算），详情页出现三个并列动作「继续推进」／「先放回酝酿」／「安静放下」；界面不显示停滞天数、不显示进度百分比、不再发送第二条追问；选「先放回酝酿」时已有准备过程时间线完整保留

##### 异常：推进过程中愿望本身改变
- **GIVEN** `/wish/w-101` 状态「正在发生」，原愿望「一个人去海边待两天」，时间线已有 3 条记录
- **WHEN** 用户在对话区输入「想改成和妹妹一起去」
- **THEN** 标题与隐含条件更新（同行的人：妹妹），详情页原话区上方新增「最初你说的是：一个人去海边待两天」；`种下于 2026 年 9 月` 不变；3 条准备过程记录不清空；状态保持「正在发生」

## S05.2: 重新整理一个愿望 — 交互规格

**涉及页面**：`/wish/:id#tidy` 整理半屏

**半屏动作（自上而下，按侵入性递增）**

| 动作 | 行为 | 文案 |
|------|------|------|
| 改一改它 | 进入标题与原话的行内编辑，保留首次种下时间 | 「它现在更像什么？」 |
| 暂时不提醒 | 清除时机约定，状态回「刚种下」 | 「先安静一段时间」 |
| 先放回酝酿 | 仅「正在发生」可见，状态回退，保留时间线 | 「先放回等待里」 |
| 安静放下 | 状态转「安静放下」，停止全部提醒，移入对应区 | 「它曾被认真保存过，随时可以再回来」 |
| 彻底删除 | 二级动作，需二次确认，不可恢复 | 见下 |

### 验收条件（交互级）

##### 正常：安静放下一个愿望
- **GIVEN** `/wish/w-102` 状态为「正在酝酿」
- **WHEN** 用户点底部「整理一下」→ 点「安静放下」→ 点确认
- **THEN** 半屏关闭，状态徽标变为「安静放下」（灰调圆点 + 压干叶片形状），卡片移入 `/garden?state=安静放下`；标题、原话与首次种下时间完整保留；该愿望的提醒队列被清空；确认文案与结果文案均不含「失败／放弃／未完成」，结果提示为「它曾被认真保存过，随时可以再回来」

##### 正常：改一改它
- **GIVEN** 用户在整理半屏
- **WHEN** 用户点「改一改它」，将标题从「学会滑雪」改为「和朋友学会滑雪」并保存
- **THEN** 标题更新，`种下于` 时间不变，原话区保留原始表述；状态与时机约定均不变；无「已修改 N 次」记录展示

##### 异常：尝试彻底删除
- **GIVEN** 用户在整理半屏，点击「彻底删除」
- **WHEN** 系统弹出二次确认
- **THEN** 确认层必须同时说明两者差别：「安静放下」可随时唤回、「彻底删除」不可恢复且会一并清除语音、照片与对话；默认焦点落在「取消」；用户确认后该愿望及其全部媒体与对话被清除，返回 `/garden` 并提示「已经彻底删除了」；不提供撤销

##### 异常：在「已经发生」状态下打开整理
- **GIVEN** 某卡状态为「已经发生」
- **WHEN** 用户点「整理一下」
- **THEN** 半屏仅提供「补充这页记忆」与「彻底删除」；不提供「安静放下」「暂时不提醒」「先放回酝酿」（终态不可回退）
