## ADDED — S02 增补：当下日程的第三选项「先记一下」

> 来源：s02-lite-conversion 提案。追加到 S02 的验收条件之后，修订 EX-18.2 的选项集。

#### 验收条件（EX-18.2 增补：save_as_lite）

##### 正常：选择「先记一下」转为轻事件
- **GIVEN** 用户输入「明天下午 3 点开会」，Agent 判定为 near_term_todo 并询问
- **WHEN** 用户在「就当成未来的事」「先记一下」「删掉它」三个选项中选择「先记一下」
- **THEN** 原 wish 行被删除（照片关联与任何 pending 提醒一并清除），同一事务内新建同文本的轻事件并出现在 P1「先记一下」列表中；原 wish_id 之后访问返回 404；全程无提醒产生

##### 异常：已约定时机的愿望不可转换
- **GIVEN** 某输入已被用户确认转为愿望并约定了时机（状态 brewing）
- **WHEN** 客户端对该 wish 调用转换端点
- **THEN** 服务端返回 409 拒绝转换（已确认时机的愿望转轻事件等于变相弃约，需用户先走 S03 的既有路径）；wish 数据不变

## MODIFIED — 5.3 「不做」清单

### 5.3 「不做」清单

| 不做的事 | 原因 |
|---------|------|
| 社交、多人协作、共同愿望 | 第一版聚焦个人隐私空间，社交会改变记录时的坦诚程度 |
| 愿望的私密性分级与对外分享卡 | 全部内容默认仅自己可见即已满足 MVP；分级会引入对外可见性并稀释「私密」这一前提 |
| 自动订票、支付、下单 | 涉及资金与外部账号，超出「陪伴」的边界 |
| 天气、位置与个人日历的自动推理 | 外部数据源按路线图分步落地：**法定节假日已以内置数据文件落地（holiday-aware-timing）**；天气需要供应商选型与数据出境评估、个人日历需要 OAuth 授权与隐私边界设计，各自独立提案 |
| 模型直接发送或改写提醒 | 模型只到「提议待确认」为止；提醒是否发出、何时发出仍由确定性调度器按用户已确认的时机决定 |
| ~~轻量日常事件（「晚上吃什么」类）~~ | **已落地为 S09（lightweight-events 提案）**：独立轻量记录表 + 「先记一下」入口，结构上无提醒路径 |
| ~~轻事件的 Agent 理解与建议~~（部分落地） | **理解联动已落地（s02-lite-conversion）**：near_term_todo 判定后用户可选择「先记一下」落入轻事件；**主动建议仍不做**——任何建议都会让「先记一下」变重 |
| 轻事件的照片/语音与反向转换 | 转换只保留文本；lite → wish 见 lightweight-events 路线第 3 步 |
| 视频记录 | 现有媒体管道仅覆盖文字、语音与照片；视频需补 MIME 白名单、大小／时长上限、分片续传与存储成本控制，另行提案 |
| 强制打卡、连续天数、完成率、排行榜 | 与「不制造焦虑」原则直接冲突 |
| 通用聊天机器人入口 | Agent 只围绕愿望对话，避免产品定位漂移 |
| 原生 App、桌面客户端、多语言 | 形态与范围收敛，见 5.1 |
