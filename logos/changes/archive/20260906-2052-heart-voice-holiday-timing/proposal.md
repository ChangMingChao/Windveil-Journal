# 变更提案：heart-voice-holiday-timing

> module: core | created: 2026-09-06

## 变更原因

用户以 DOCX 需求文档提出 5 条 Android 端修改（原文摘录）：
1. 底部导航改为「心语 / 未发生之地 / 已发生之书 / 我的」；随手记收进「未发生之地」顶部切换；「心语」是调用大模型的聊天框（配置在「我的」页：url + api key），负责接收用户输入并分析有用信息（如「我明天做点什么好呢」隐含明天有空，可记录），无关信息不记。
2. 问：大模型能调用吗？为什么显示「它暂时没想出来，你可以自己选一个时候。」
3. 自己选时机支持枚举法定节假日（一个或多个）、或具体年月日、或「让它提个时候」但要真正能分析。
4. 问：「准备过程」的具体作用（由用户判断是否移除）。
5. 移除「整理它」模块，具体状态由大模型结合分析。

## 收敛决策（请重点确认）

| 决策点 | 本提案 | 理由 |
|--------|--------|------|
| 心语 = 客户端直连 LLM | Android 端直接调用用户在「我的」页配置的 OpenAI 兼容 `/chat/completions` 端点（Base URL / API Key / 模型名存本地 DataStore），不经后端转发 | 用户文档明确「配置在我的里进行 url 和 api key 配置」；隐私上聊天内容不进服务端 |
| 心语的记录动作 | 模型判定「对未来安排有用的事实」→ 客户端自动调用既有 `POST /lite-events` 记为轻事件；无关不记 | 复用既有轻事件结构（纯记录、无提醒路径），零新增服务端结构 |
| 「让它提个时候」真正分析 | 走既有 `POST /wishes/{id}/timing-proposals`，由**服务端 env** 配置的 LLM 提供分析；本地联调需在 backend `.env` 配置可用端点。客户端心语配置不回传后端（不做配置同步，属后续提案） | 契约边界：模型提议→服务端校验→用户确认的链路不变 |
| 降级文案解释（问题 2） | 「它暂时没想出来」= 后端 propose_timing 调 LLM 失败/超时的降级路径（EX-P.1）。当前本地 `.env` 的 `LLM_BASE_URL=127.0.0.1:9100` 是演练 mock，不可达，所以必然降级；配置真实端点后即可分析 | 属配置问题而非缺陷 |
| 自己选时机 = 三类 | ① 法定节假日（多选，新增 `type=holiday` + `holidays[]`，复用内置节假日数据文件计算最近一个匹配日）② 具体年月日（既有 `month_day` 完整日期）③ 让它提个时候。季节/数月后/空闲周末/累了/自己想起从 UI 移除（后端枚举保留，Web 端不受影响） | 用户文档第 3 条；后端是「服务端计算 next_trigger_at」硬约束的必要配合 |
| 整理它 | 移除 我好像准备好了/还不是现在/暂时不提醒/先放回酝酿/安静放下 五个手动按钮；**保留「它已经发生了」**（S06 记忆页唯一入口）与「彻底删除」（数据出口必须保留）；状态推进后续由心语分析驱动（本批先移除入口，不实现状态分析） | 用户文档第 5 条；S06 是 P0 场景不能断 |
| 准备过程（问题 4） | **本批保留不删**。作用见「问题回答」：它是 S04 拆解执行的时间线，也是 S06 记忆页「经过」的草拟素材与 60 天停滞判定依据；是否移除待用户判断 | 用户文档第 4 条 |
| 底栏与随手记 | 四 Tab：心语/未发生之地/已发生之书/我的；未发生之地内顶部 Tab「愿望 | 随手记」 | 用户文档第 1 条 |

## 变更类型
接口级（新增 `type=holiday` + `GET /holidays`）+ Android UI 级

## 变更范围
- 影响的需求文档：5.3 「不做」清单原「心语部分放开」表述归属修订（归入本提案）
- 影响的技术架构：无新增组件（LLM 直连为客户端行为）
- 影响的 API：
  - `api/wishes.yaml` — TimingInput.type 增 `holiday`、新增 `holidays` 数组、新增 `GET /holidays` 端点
- 影响的 DB 表：无（timing_type/timing_value 为既有列，存 holiday 名）
- 影响的后端代码：`app/timing.py`（holiday 计算）、`app/holidays.py`（next_holiday_occurrence）、`app/services.py`（透传 holidays）、`app/api.py`（holidays 端点 + 透传）
- 影响的 Android 代码：导航/底栏、Garden 顶部 Tab、新增 HeartVoiceScreen + LLM 配置页区块、WishDetail 时机区与整理区重构
- 影响的测试：后端 holiday 计算 UT（新 deltas/test）；Android MockWebServer 用例补充

## 追加范围（用户 2026-09-06 追加）
「我的」页二级化：随大模型配置卡加入，页面内容膨胀为六块。按分类收纳进四个二级页——「心语与模型」（LLM 配置）、「它记得我什么」（偏好条目 + 我的理解 + 什么时候有空，S08 一体）、「提醒」（通道开关，S10）、「账号」（邮箱绑定 + 登出）；主页面改为菜单入口。纯客户端信息架构调整，无 API/契约变更。

## 明确不做（本提案边界）
- 不做心语配置同步到后端（「让它提个时候」用服务端 env 配置）；
- 不做心语驱动的愿望状态自动推进（整理按钮先移除，分析驱动后续提案）;
- 不删除后端 season/after_months/free_weekend/when_tired 枚举与 Web 端入口；
- 不做语音输入与图片消息。

## 部署影响
- 是否需要部署：否（本地联调验证；生产部署需单独授权）
- 是否涉及数据迁移：否
- 是否需要 smoke：不新增
