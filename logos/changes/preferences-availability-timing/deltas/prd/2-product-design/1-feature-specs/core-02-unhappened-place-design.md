## ADDED — S03 增补：时机建议（TimingProposal）— 交互规格

**涉及页面**：`/wish/:id`（P3 详情）时机区 → `#timing-advice` 确认半屏

**时机区增补**

| 元素 | 规格 |
|------|------|
| 「让 Agent 提个时候」 | 位于「什么时候再提起它」下方的次级文字链（非按钮样式，不与主动作竞争）；仅 `seeded`（未约定时机）状态显示 |
| 建议卡片（待确认） | 纸色 `card` 底，含：建议时机（复用 6 选项卡面文案，如「入冬」）、一句理由（引用依据，如「因为你说过周六上午通常有空」「你在九月提过想赶在冬天前学会」）、置信档（「大概猜的」/「比较确定」）、来源条目列表、「就这样定」+「先不定」两个出口 |
| 建议卡片（已决策） | 已确认：卡片收起为一行「你在 <日期> 采纳了它的建议」；已拒绝：不再展示；已失效（超时或依据被删）：卡片变灰并显示「这条建议过期了，可以再要一条」，不自动重新生成 |

**明确不存在的元素**（验收要检查其缺失）：建议的裸百分比数字、技术错误码、「AI 推荐」字样、建议自动转为提醒的任何提示、被拒绝建议的再次自动弹出。

**交互流程**

1. 用户在 P3 时机区点「让 Agent 提个时候」
2. 半屏内出现「它在想了…」的轻态（≤5 秒；超时降级为「它暂时没想出来，你可以先自己选一个」+ 6 选项入口，不阻塞）
3. Agent 产出建议 → 展示建议卡片（时机 + 理由 + 置信档 + 依据条目）
4. 用户点「就这样定」→ 服务端校验通过后按 S03 既有规则写入时机（等价于用户手动选了该选项），状态转「正在酝酿」，卡面更新
5. 用户点「先不定」→ 建议记为已拒绝，返回时机半屏；同一依据组合不被反复推销
6. 依据条目（偏好/可用时段）被用户撤回或删除 → 未确认的建议标记失效

### 验收条件（交互级）

##### 正常：采纳一条时机建议
- **GIVEN** `/wish/w-102`（「学会滑雪」）状态「刚种下」，用户已声明可用时段「周六上午通常有空」
- **WHEN** 用户点「让 Agent 提个时候」→ 卡片显示建议「一个空闲的周末」，理由「你说过周六上午通常有空」，置信档「比较确定」→ 用户点「就这样定」
- **THEN** 半屏关闭，卡片状态徽标变为「正在等待合适的风：一个空闲的周末」，`/garden` 同步；该建议显示为「你采纳了它的建议」；通知、提醒与周预算行为与用户手动约定时机完全一致（S03 既有规则）

##### 正常：拒绝建议后不被反复推销
- **GIVEN** 同上场景，用户点了「先不定」
- **WHEN** 用户再次打开时机区
- **THEN** 已拒绝的建议不再展示；系统不自动再生成新建议；「让 Agent 提个时候」入口仍在，由用户主动再次触发；用户手动选择 6 选项之一的行为不受任何影响

##### 异常：建议生成失败或超时
- **GIVEN** 用户点「让 Agent 提个时候」，LLM 5 秒内未返回或返回不可用
- **WHEN** 半屏达到超时
- **THEN** 显示「它暂时没想出来，你可以先自己选一个」并保留 6 选项入口；不出现错误码；可再次点击重试；愿望状态与数据无任何变化

##### 异常：建议依据被撤回或删除
- **GIVEN** 一条待确认建议引用了偏好「周六上午通常有空」
- **WHEN** 用户在 P6「它记得我什么」撤回或删除该条目
- **THEN** 该建议立即标记失效（半灰态「这条建议过期了，可以再要一条」）；确认接口拒绝已失效的建议（不产生任何写入）；不发送任何通知
