# S10: 管理提醒通道 — 交互规格

> 模块：core｜阶段：Phase 2 产品设计（What）
> 上游场景：`core-01-requirements.md` 的 S10（notification-channels 提案新增）
> 原型：无新增屏——P6「我的」内的开关区，复用既有设计令牌

**涉及页面**：`/me#channels`（P6 我的）「提醒通道」区

**「提醒通道」区结构**

| 元素 | 规格 |
|------|------|
| 标题 | 「提醒通道」+ 一句说明「安静是你的选择，随时可以打开」 |
| 推送开关 | 独立 toggle（44×44 触控区）；开启时副文案「浏览器推送」 |
| 邮件开关 | 独立 toggle；开启时副文案「邮件兜底（iOS 建议保持开启）」 |
| 全关文案 | 两个开关都关闭时显示「先安静一段时间，想听的时候随时打开」——无内疚感、无挽留 |
| 状态反馈 | 切换即时生效并回显最新状态；失败时回滚开关并提示「没能保存，再试一次」 |

**明确不存在的元素**（验收要检查其缺失）：确认弹层（切换不需要确认）、冷静期倒计时、内疚文案（「你将错过…」）、按愿望粒度的开关、免打扰时段设置。

**交互流程**

1. 用户进入 P6 → 「提醒通道」锚点区显示两个开关的当前状态（来自 `GET /me`）
2. 切换任一开关 → `PATCH /me/notification-channels` → 即时生效
3. 关闭推送（邮件开启）→ 之后的提醒只走邮件；已注册的推送订阅数据保留
4. 全部关闭 → 显示全关文案；已到期提醒顺延等待，重开后自然恢复
5. 重新打开 → 顺延中的提醒按周预算恢复投递

### 验收条件（交互级）

##### 正常：关闭推送保留邮件
- **GIVEN** 用户在「提醒通道」区，推送开启、邮件开启
- **WHEN** 用户关闭推送开关
- **THEN** 开关立即反映新状态；无确认弹层、无挽留文案；邮件开关状态不变

##### 正常：全部关闭的完全静默
- **GIVEN** 两个开关均开启，outbox 中有 pending 提醒
- **WHEN** 用户依次关闭两个开关
- **THEN** 显示全关文案「先安静一段时间，想听的时候随时打开」；重新打开邮件后，顺延中的提醒按周预算恢复投递；全程愿望与轻事件数据不受影响

##### 异常：保存失败回滚
- **GIVEN** 服务端暂时不可用
- **WHEN** 用户切换开关
- **THEN** 开关视觉回滚到切换前状态并提示「没能保存，再试一次」；不出现错误码；可重试
