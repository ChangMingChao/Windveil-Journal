# 变更提案：standalone-mode

> module: core | created: 2026-09-06

## 变更原因

用户决策：Android 端改为**纯单机模式**——数据存本机、不设登录账号，愿望理解/步骤生成复用「心语」的用户自配模型（使用期间静默分析），提醒走**系统日历**（记录待发生事件、由系统能力在合适时间提醒），删除邮件通道。

## 收敛决策（请重点确认）

| 决策点 | 本提案 | 理由 |
|--------|--------|------|
| 数据层 | Room 本地库承载全部数据（愿望/轻事件/记忆页/时机），schema 从既有 API 契约直译 | 单机权威；不再依赖后端 SQLite |
| 账号 | 移除登录/绑定邮箱/匿名建号流程，无用户概念（单用户单表空间） | 用户明确「可以不设置登录账号」 |
| 愿望理解/步骤生成/时机建议 | 全部走心语的用户自配模型（客户端直连），在用户使用期间触发；**模型未配置时降级**：保存原话、跳过理解/建议（与既有 degraded 语义一致） | 用户指定「使用心语模型，分析过程静默完成」 |
| 隐私红线 | 分析只把「必要的最小上下文」（原话/已有理解摘要）发给用户自己配的模型；不上传任何第三方服务器（除用户配置的模型端点本身） | 沿用心语既有隐私边界 |
| 提醒 | 约定时机时把「待发生事件」写入**系统日历**（CalendarProvider，需用户授权日历权限），由系统在触发时间发提醒；App 内同时显示「今天风来了」列表 | 用户指定「打开本机日历 + 系统能力提醒」；避免自建推送/AlarmManager 对抗 ROM 杀后台 |
| 邮件通道 | 删除（提醒设置页只留系统日历开关） | 用户明确「邮件通道删除」 |
| 触发时刻计算 | `timing.py` 的算法**移植为 Kotlin**（季节/纪念日/数月后/空闲周末/法定节假日多选），内置节假日 JSON 随 APK 打包；移植以既有 UT-S03-55~58 为验收基准逐条对齐 | 服务端计算的硬约束转为「端上确定性计算」，算法与测试双保险 |
| 状态机 | 六状态流转规则原样移植（Room 内校验） | 与 Web 端语义一致 |
| 心语自动记录 | 保留（识别有用信息 → 写本地轻事件表） | 既有行为，改写入目标为本地 |
| 服务端/后端 | Android 不再调用；backend/ 与 Web PWA 保持现状不动（服务端模式仍可用，但本提案不维护双模切换） | 用户决策「就使用单机模式」 |
| 数据导出 | 设置页新增「导出 JSON」按钮（愿望/轻事件/记忆页全量导出到下载目录） | 单机数据无服务端兜底，最低限度可携带 |

## 变更类型
代码级（Android 重构）+ 需求级（产品形态从「客户端-服务端」收敛为「单机 App」）

## 变更范围
- 影响的需求文档：5.1 产品形态补记「Android 单机模式」
- 影响的技术架构：架构文档 3.4 Android 节改写（Room/日历/心语模型承担分析）
- 影响的 API：无服务端变更（Android 不再消费 API；契约文件保留供 Web 端与历史追溯）
- 影响的 DB 表：新增 Room schema（wishes/lite_events/memories/timing）
- 影响的 Android 代码：
  - data 层：Retrofit/OkHttp/TokenStore/CookieJar 移除 → Room DAO + Repository 重写
  - 时机：TimingCalculator（Kotlin 移植）+ HolidayData（assets 打包）
  - 提醒：CalendarReminder（CalendarProvider 写入/删除事件）
  - LLM：HeartVoiceClient 复用，新增 AnalysisService（理解/步骤/时机建议的 prompt 与 JSON 解析）
  - UI：删欢迎页/账号页；设置页改「心语与模型/提醒（日历）/数据导出」
- 影响的测试：TimingCalculator UT（对齐 UT-S03-55~58 语义）、状态机 UT、心语解析 UT

## 明确不做（本提案边界）
- 不做端到端加密同步/多设备（数据导出 JSON 兜底）；
- 不做 Web Push 与 FCM（系统日历提醒替代）；
- 不做后台自启分析（分析仅发生在用户使用期间）；
- 不改 backend/ 与 Web PWA（服务端模式代码保留，不新增功能）。

## 部署影响
- 是否需要部署：否（纯 Android 端）
- 是否涉及数据迁移：否（Room 全新建库；无旧数据兼容问题——此前数据在后端，单机版从零开始）
- 是否需要 smoke：否
